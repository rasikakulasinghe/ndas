# NDAS Architecture Reference

> **Generated by:** BMAD document-project workflow (Step 8)
> **Project:** Neurodevelopmental Assessment System (NDAS)
> **Pattern:** Django MTV (Model-Template-View), server-side rendering, HTMX for dynamic updates

---

## High-Level Architecture

```
Browser
  │ HTTPS requests
  ▼
Nginx (Production)
  │ Proxies to UNIX socket
  ▼
Gunicorn (3 workers, 300s timeout)
  │ WSGI
  ▼
Django Application (ndas.settings)
  │
  ├── 13-Layer Middleware Stack
  ├── URL Router (ndas/urls.py)
  │     ├── patients (root /)
  │     ├── users (/users/)
  │     ├── video (/video/)
  │     ├── reports (/reports/)
  │     └── problemlist (/problems/)
  │
  ├── Views (function-based)
  │     └── @login_required + @ratelimit + @handle_view_errors
  │
  ├── Models (ORM)
  │     └── All inherit TimeStampedModel + UserTrackingMixin
  │
  └── Templates (Jinja2-like Django, AdminLTE 3.2)
        └── base.html → content_block → app templates

Storage
  ├── SQLite (dev) / PostgreSQL (prod)
  ├── Local filesystem (media/videos/, media/attachments/)
  └── WhiteNoise (static files in production)

Cache
  └── Redis (prod) / LocMemCache (dev)
```

## Middleware Stack (Order is Critical)

The middleware ordering in `ndas/settings.py` MUST NOT be reordered. Each position serves a specific purpose:

| Position | Middleware | Why This Position |
|----------|-----------|-------------------|
| 1 | `SecurityMiddleware` | First — HTTPS redirect, HSTS headers BEFORE any processing |
| 2 | `WhiteNoiseMiddleware` | Second — serves static files before request hits Django views |
| 3 | `CSPMiddleware` | Before session/auth — Content Security Policy nonces generated early |
| 4 | `AdditionalSecurityHeadersMiddleware` (custom) | X-Content-Type-Options, X-Frame-Options, Referrer-Policy |
| 5 | `SessionMiddleware` | Must be before AuthenticationMiddleware |
| 6 | `CommonMiddleware` | Append slash, URL normalization |
| 7 | `CsrfViewMiddleware` | CSRF protection before any POST handling |
| 8 | `AuthenticationMiddleware` | After session — attaches user to request |
| 9 | `UserActivityMiddleware` (custom) | After auth — auto-populates added_by/last_edit_by on all saves |
| 10 | `MessageMiddleware` | Django messages framework |
| 11 | `XFrameOptionsMiddleware` | Clickjacking protection |
| 12 | `UserAgentMiddleware` | Device detection (is_mobile, browser, OS) |
| 13 | `SubscriptionCheckMiddleware` (custom) | Last — blocks access if subscription expired |
| 14 | `SecurityHeadersValidationMiddleware` | Production only — validates security headers are set correctly |

## Data Flow: Typical Clinical Request

```
1. User navigates to /assessment/add/<ptid>/<fid>/
2. SecurityMiddleware → HTTPS check
3. WhiteNoiseMiddleware → not static, pass through
4. CSPMiddleware → inject nonce into request for inline scripts
5. SessionMiddleware → load session
6. CsrfViewMiddleware → check CSRF token (POST) or inject (GET)
7. AuthenticationMiddleware → attach CustomUser to request.user
8. UserActivityMiddleware → set request._user for auto-tracking
9. SubscriptionCheckMiddleware → verify Subscription.status == 'active'
10. URL Router → patients.urls → assessment_add view
11. @login_required → redirect to user-login if not authenticated
12. @ratelimit → check 10/m limit per user/IP
13. @handle_view_errors → wrap in try/except
14. View logic: get_object_or_404(Patient), get_object_or_404(Video)
15. Form render (GET) or form.save() (POST)
    └── Model.save() triggers full_clean() → validates fields
    └── UserActivityMiddleware auto-sets added_by/last_edit_by
16. Redirect on success or render template on error
```

## Cross-App Dependency Graph

```
patients ←──────────────────── users
   │            FK added_by      │ CustomUser
   │                              │ Subscription (gates access)
   │
   ├── Video (video app)
   │     └── GMAssessment (patients) — critical O2O coupling
   │           └── Delete blocked if assessment exists
   │
   ├── Problem (problemlist app)
   │     └── ProblemAction → AUTH_USER_MODEL (users)
   │
   └── ReportTemplate/Config (reports app)
         └── PDF generators read Patient + all assessments
```

**Critical coupling:** `video.Video` ↔ `patients.GMAssessment`
- Each Video has at most ONE GMAssessment (OneToOne)
- Video cannot be deleted if a GMAssessment references it (`validate_can_delete` in delete_helpers.py)
- GMA add view takes both `<ptid>` and `<fid>` (patient ID + video/file ID)

## Security Architecture

### Input Security

| Layer | Mechanism |
|-------|-----------|
| HTML sanitization | `sanitize_html()` (bleach, medical-safe tags) before storing rich text |
| Text sanitization | `sanitize_text_input()` removes XSS, preserves `BP < 120/80` medical notation |
| File validation | MIME type checking (python-magic), size limits, virus scan (placeholder) |
| Filename sanitization | `sanitize_filename()` — no path traversal, no hidden files |
| Search inputs | `sanitize_search_query()` — removes HTML + injection chars |
| SQL injection | Django ORM parameterization (no raw SQL except aggregations) |

### Access Control

| Level | Mechanism |
|-------|-----------|
| Authentication | `@login_required(login_url="user-login")` on all views |
| Session | 1-hour timeout, browser-close expiry, `SESSION_COOKIE_SECURE=True` in prod |
| CSRF | Django `CsrfViewMiddleware` + `{% csrf_token %}` in all forms |
| Rate limiting | `@ratelimit(key='user_or_ip', rate='10/m')` create/edit, `5/m` delete |
| Delete permissions | `has_delete_permission(user, entity)` — superusers global, staff own records |
| Subscription gate | `SubscriptionCheckMiddleware` blocks all views if `status != 'active'` |

### HTTP Security Headers

Set by `CSPMiddleware` + `AdditionalSecurityHeadersMiddleware`:
- `Content-Security-Policy` with nonce-based inline script control
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Strict-Transport-Security` (production)
- `Referrer-Policy: strict-origin-when-cross-origin`

## Database Configuration

### Dual Database Setup

```python
# Development (default)
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.sqlite3',
        'NAME': BASE_DIR / 'db.sqlite3',
    }
}

# Production (via environment variables)
# DB_ENGINE=django.db.backends.postgresql
# DB_NAME, DB_USER, DB_PASSWORD, DB_HOST, DB_PORT
```

### Key Database Patterns

- All models use composite indexes (explicitly defined in `Meta.indexes`)
- `db_index=True` on all searchable/filterable fields
- `select_related()`/`prefetch_related()` required in all views with related data
- `UniqueConstraint` on Video (patient, recorded_on, title)
- Transactions used in ReportTemplate.save() for atomic default management

```
media/
├── videos/
│   └── YYYY/MM/patient_name/filename_timestamp.ext   ← get_video_path_file_name()
├── videos/compressed/

└── tutorials/YYYY/MM/                                ← Help videos
```

### File Size Limits

| Type | Limit | Setting Key |
|------|-------|------------|
| Video | 2GB | `settings.FILE_UPLOAD_LIMITS['VIDEO_MAX_SIZE']` |
| Image | 10MB | `settings.FILE_UPLOAD_LIMITS['IMAGE_MAX_SIZE']` (also `MAX_IMAGE_SIZE`) |
| Document | 100MB | `settings.FILE_UPLOAD_LIMITS['MAX_FILE_SIZE']` |
| Profile Picture | 5MB | Enforced in validators |

## Caching Architecture

```python
# Development
CACHES = {'default': {'BACKEND': 'django.core.cache.backends.locmem.LocMemCache'}}

# Production (with Redis)
CACHES = {
    'default': {
        'BACKEND': 'django.core.cache.backends.redis.RedisCache',
        'LOCATION': REDIS_URL,  # redis://localhost:6379/0
    }
}
```

Cache usage:
- `Subscription.status` — cached to avoid DB hit on every request
- Rate limiting counters (`django-ratelimit`)
