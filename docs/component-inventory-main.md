## Template Architecture

### Inheritance Hierarchy

```
base.html                    ← All authenticated views (extends AdminLTE layout)
│   ├── navbar.html          (block: top nav, user dropdown, search bar)
│   ├── main_sidebar_menu.html (block: left nav menu, collapsible)
│   ├── content_headder.html (block: page title + breadcrumb)
│   ├── main_content.html    (block: main_content ← apps write here)
│   ├── main_footer.html     (block: footer)
│   ├── control_sidebar.html (block: right sidebar)
│   └── messages.html        (Django flash messages → toast/alerts)
│
basic_plane.html             ← Public/unauthenticated views (login, password reset)
    └── (minimal layout, no sidebar/nav)
```

### Template Block Convention

```django
{% extends 'src/base.html' %}
{% load static %}

{% block title %}Section - Action{% endblock %}

{% block main_content %}
<div class="container-fluid">
  {% csrf_token %}
  <!-- content here -->
</div>
{% endblock %}
```

## Shared Partials

All partials are in `templates/src/partials/` or `templates/src/`:

| Partial | Include Syntax | Purpose |
|---------|----------------|---------|
| `src/messages.html` | Auto-included in base | Django `messages` framework toasts/alerts |
| `src/form_error.html` | Manual `{% include %}` in forms | Field-level form errors with Bootstrap styling |
| `src/logout_modal.html` | Auto-included in navbar | Logout confirmation modal |
| `src/logout_modal_simple.html` | Alternative modal | Simplified logout modal |
| `src/partials/delete_confirmation_modal.html` | `{% include %}` on pages with delete | Universal delete confirm modal |

### Delete Confirmation Modal Usage

```django
{% load delete_modal_tags %}
{% include 'src/partials/delete_confirmation_modal.html' %}
```

Data is passed via template context:
- `entity_display_name` — what is being deleted
- `warning_items` — list of cascade warnings
- `detail_items` — dict of entity details
- Delete form posts to `entity_delete_url`

## Key UI Patterns

### List Views (`manager.html`)
- DataTables for server-side sortable/searchable tables
- Filter tabs at top (e.g., All / New / Diagnosed / Discharged for patients)
- Action buttons: View, Edit, Delete (permission-checked)
- Consistent card layout with AdminLTE `card` component

### Detail Views (`view.html`)
- AdminLTE card with tabbed content for related records
- Patient view is the most complex — embeds all assessment tabs
- Breadcrumb navigation in `content_headder.html`
- Action buttons (Edit, Delete, Bookmark, Print)

### Form Views (`add.html` / `edit.html`)
- Django forms rendered with Bootstrap 4 field styling
- Select2 for M2M fields (diagnosis selection in GMA)
- CKEditor for RichTextField inputs (medical history, CDIC assessment text)
- File upload with progress indication in video `add.html`
- Client-side validation with server-side validation fallback

### HTMX Patterns
- `hx-post` for status changes (`problem-status-change`)
- `hx-get` for partial page refreshes (user activity API)
- `hx-target` and `hx-swap` for updating DOM sections without full reload
- `hx-indicator` for loading spinners

## Template Directory for New Features

When adding a new entity, follow this pattern:

```
templates/
└── {entity_name}/         ← snake_case directory
    ├── manager.html       ← list view
    ├── add.html           ← create form
    ├── edit.html          ← update form
    └── view.html          ← detail view
```

And extend the correct base:
```django
{% extends 'src/base.html' %}    ← authenticated features
{% extends 'src/basic_plane.html' %}  ← public pages only
```
