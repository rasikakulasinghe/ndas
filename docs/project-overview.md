## What is NDAS?

**NDAS** (Neurodevelopmental Assessment System) is a Django-based web application for managing patient records and conducting video-based neurodevelopmental assessments for infants and young children.

The system is designed for use in clinical settings (hospitals, child development centres) where healthcare staff need to:
- Register and track newborn/infant patients
- Upload and manage video recordings of infant movements
- Conduct and document multiple types of neurological/developmental assessments
- Track clinical follow-up care and discharge planning
- Generate professional PDF/Excel reports

## Clinical Domain

### Patient Population
Infants and young children (0–6 years) referred for neurodevelopmental assessment, typically including:
- Premature infants (POG 20–44 weeks)
- Infants with birth complications (low APGAR, resuscitation required)
- Children with suspected neurological or developmental abnormalities

### Assessment Types

| Assessment | Acronym | Purpose | Key Output |
|-----------|---------|---------|-----------|
| General Movement Assessment | GMA | Video-based neurological screening | NORMAL / ABNORMAL diagnosis |
| Hammersmith Infant Neurological Examination | HINE | Scored neurological exam (0–78) | Score + severity category |
| Child Development & Intervention Centre | CDIC | Ongoing rehabilitation tracking | Session records + discharge |
| General Paediatric Assessment | GPA | Routine clinical evaluation | Multi-domain clinical record |
| Developmental Assessment | DA | 4-domain developmental screening | GM / FMV / HSL / SEB age ranges |

### Clinical Identifiers

| NNC | — | Secondary patient number |

## System Capabilities

### Patient Management
- Register patients with full birth data (POG, birth weight, APGAR, delivery mode)
- Track antenatal, intranatal, and postnatal history (rich text)
- View patient status: New → Under Assessment → Diagnosed → Discharged
- Filter patients by diagnosis status, assessment type, discharge state
- Search across BHT, NNC, name, and other identifiers

### Video Management
- Upload clinical assessment videos (mp4, mov, avi, mkv, webm — up to 2GB)
- Automatic metadata extraction (duration, resolution, codec) via moviepy/ffprobe
- Video playback via Video.js player
- Track unassessed vs assessed videos
- Videos linked one-to-one with GMA assessments

### Assessment Workflows
- GMA: link video → select diagnoses from DiagnosisList → set conclusion (NORMAL/ABNORMAL) → management plan → follow-up scheduling
- HINE: enter score (0–78) → auto-categorize severity
- CDIC: progressive session records → discharge tracking
- GPA: comprehensive clinical evaluation → discharge tracking
- DA: 4-domain developmental age ranges → auto-calculated is_normal

### Attachments
- Upload images, PDFs, videos, documents per patient
- File type and size validation (MIME-type aware)
- Virus scan status tracking (placeholder — ClamAV integration TODO)
- Access level control (restricted/team/department/general)

### Problem List
- Active problem tracking per patient
- Severity classification (mild/moderate/severe/life-threatening)
- Status workflow (active/resolved/chronic/inactive)
- Action logging with timeline view
- Aggregate analysis and export

### Bookmarks
- Bookmark any entity (Patient, Video, GMA, HINE, Attachment, DA, CDIC, GPA)
- Generic FK pattern (bookmark_type + object_id)
- Tags, priority levels, public/private visibility

### Reporting
- PDF generation for each assessment type (reportlab)
- Excel reports with filtering, anonymization, multi-sheet support
- Configurable templates (header/footer/logo via ReportTemplate)
- Report history and file management

### User Management
- CustomUser with staff position tracking
- Admin panel for user creation/edit/deactivation
- Activity logging with device + geolocation data
- Session management (view/terminate active sessions)
- Email verification flow
- Rate-limited password reset

### Subscription System
- Singleton Subscription model (free/commercial)
- Grace period support
- System-wide gate via SubscriptionCheckMiddleware
- Cache-backed status properties

## Key Architectural Decisions

1. **Centralized custom_codes** — All validators, choices, utilities live in `ndas/custom_codes/`. No duplication allowed.

2. **Mandatory base models** — All models inherit `TimeStampedModel` + `UserTrackingMixin`. Auto-tracking via middleware, not manual field assignment.

3. **Delete system** — `delete_helpers.py` enforces permissions and business rules. Video deletion blocked when GMA assessment exists.

4. **Server-side rendering** — No REST API (except minor HTMX endpoints). All responses are HTML templates. Keeps the system simple and secure.

5. **Dual database** — SQLite for development (easy setup), PostgreSQL for production (scale + reliability).

6. **Security-first middleware** — 13-layer ordered stack cannot be reordered. CSP nonces, rate limiting, subscription gating all enforced at middleware level.

7. **Medical notation preserved** — Sanitizers are carefully tuned to preserve `BP < 120/80`, `Temperature > 38°C` while blocking XSS.
