# Fix IDOR/cross-tenant ownership gaps

## Intent

**Problem:** Three unrelated authorization gaps, all in the IDOR/cross-tenant class, from the 2026-08-25 whole-app bmad-review: (1) `referral/views.py`'s thread-panel and reply views authorized access by institution membership alone, letting any colleague at either institution — not just the two assigned clinicians — read a referral's frozen patient snapshot and post replies; (2) `reports/views.py`'s `delete_report` had no ownership check before deleting a file, and `report_history` listed every user's report filenames to every other authenticated user; (3) `institution/views.py`'s `protected_media_view` enforced institution-slug isolation for video/attachment media paths but not for institution logo paths.

**Approach:** Added a shared `_is_thread_participant()` check (from_clinician/to_clinician, or an institution ADMIN) to both referral thread views. Reused the existing session-keyed cache ownership check from `download_report` in `delete_report`, and applied the same check to filter `report_history`'s listing. Added `'logo'` to `protected_media_view`'s isolation-checked path segments (case-insensitively, per blind-hunter review — NTFS resolves paths case-insensitively).
